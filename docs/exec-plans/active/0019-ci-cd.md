# 0019 — CI/CD with GitHub Actions

## Context

Deploys to AWS (0017) were manual and unchecked. Done means: every PR to `main` runs the web and Python checks, and every push/merge to `main` runs them and, only if they pass, deploys to AWS automatically.

## Design

- `ci.yml`: jobs `web` (ESLint, `tsc`), `python` (ruff check, ruff format check, pytest) and `deploy`, which needs both and calls `deploy.yml`. Triggers: PRs to `main` and pushes to `main`; deploy runs on push only.
- `deploy.yml` gains `workflow_call` (manual `workflow_dispatch` stays), a non-cancelling `deploy` concurrency group and the `production` environment.
- The deploy job is skipped until the `AWS_ROLE_ARN` variable exists, so CI stays green before the AWS OIDC role is created.
- ESLint (flat config, typescript-eslint, react-hooks, react-refresh) is new for `apps/web`; `make lint-web` runs it with `tsc`, so `make check` matches CI.

## Steps

1. Add ESLint to `apps/web`; fix real errors.
2. Add `ci.yml`; make `deploy.yml` reusable.
3. Update `infra/README.md`, AGENTS.md and the tech-debt tracker.
4. One-time AWS OIDC role and GitHub variables/secret (manual, see `infra/README.md`).

## Verification

- `make check` passes locally.
- Open a PR: `web` and `python` run, `deploy` is skipped.
- Merge to `main`: checks run, then deploy runs (or is skipped if `AWS_ROLE_ARN` is unset).
- A deliberate type error on a PR fails the `web` job.
